# Trace Authored Map Reference

Create an exact source-of-truth transcription before implementation. This skill owns
reference interpretation and approval; it does not own the later generator design.

Read the authored-map cases in
`docs/development/problem-solving-casebook.md` before starting.

## 1. Freeze implementation while the source is disputed

Do not tune the generator, replace fixtures, or declare visual equivalence while the
reference itself is unresolved. Preserve the original file unchanged. Record its path,
dimensions, hash when practical, and any known authoring context.

If the source is too large for an inspection tool, create a clearly named derived preview
at a supported size. Keep the original as authority; tool limitations never justify a
lower-fidelity acceptance criterion.

## 2. Define the coordinate register

Before tracing cells, write down:

- hex orientation and coordinate convention;
- origin and axis directions;
- row/column or axial offset rules;
- scale or pitch used only for display;
- expected footprint bounds and cell count if known;
- how stacked height, terrain, routes, landmarks, and annotations are represented; and
- which marks are ambiguous or outside scope.

Prove the register with at least three non-collinear landmarks or boundary points. A trace
that is shifted, mirrored, rotated, or uses the wrong offset convention is not approximate;
it is a different map.

## 3. Build a neutral transcription

Trace the reference into an implementation-neutral artifact before encoding generator
rules. The neutral artifact should make each authoritative cell inspectable and should
separate:

1. footprint or occupancy;
2. elevation or other scalar layers;
3. paths, bridges, regions, and landmarks; and
4. labels or review annotations.

Do not infer symmetry, smooth curves, procedural noise, or missing cells merely because
they would be convenient to generate. Mark ambiguity explicitly instead of silently
interpolating it.

Render the trace at both whole-map scale and a zoom where individual cells and coordinates
can be checked. Use multiple viewports when a single view would crop the footprint.

## 4. Obtain source approval

Present the neutral trace—not a generated in-game rendering—for approval. State the
register, layer meanings, cell count, unresolved marks, and revision. Ask the user to
approve or correct that artifact before changing code.

Approval is revision-specific. Any later change to coordinates, membership, layer values,
or ambiguous marks creates a new revision and invalidates prior galleries and fixtures.

## 5. Encode an independent literal oracle

After approval, encode the trace as literal typed data or a checked-in fixture with
provenance back to the approved revision. Test at least:

- exact cell membership and count;
- coordinate register and landmark positions;
- every authored layer or route;
- round-trip or serialization stability when applicable; and
- rejection of shifted, mirrored, rotated, truncated, and stale revisions.

The generator under test may consume the oracle, but its own output must never generate
the expected data used to validate it. A gallery that shows only generated output is
presentation evidence, not independent transcription evidence.

## 6. Hand off to generation

Only after the literal oracle is approved may implementation derive bounded, seeded, or
procedural behavior from it. Keep exact source fidelity tests separate from aesthetic or
runtime tests. If exact fidelity and procedural variation conflict, stop and surface the
product decision rather than weakening the oracle.

For a very large implementation, continue with `$develop-large-world-features`. For fresh
in-game presentation evidence, use `$inspect-game-renders` after logic gates pass.

## Completion Gate

The reference phase is complete only when the exact revision is identifiable, every cell
and layer is inspectable, the user approved the neutral artifact, the literal oracle is
independent of generated output, and stale revisions fail loudly.

## Stop Conditions

- The coordinate register cannot be proved from the available source.
- A mark changes authoritative topology but remains ambiguous.
- The proposed preview crops or hides part of the footprint.
- The only expected result available was generated by the implementation being tested.
- The user disputes the trace. Return to the neutral artifact; do not keep tuning code.
